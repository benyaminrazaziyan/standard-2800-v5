# Standard 2800-V5 — نسخه توسعه‌ای

اپلیکیشن Flutter با رابط فارسی برای محاسبات مقدماتی لرزه‌ای بر اساس روابط موجود در فایل اکسل کاربر.

## امکانات فعلی
- ورودی ارتفاع، اهمیت، سیستم سازه‌ای، ضریب رفتار، Ss/S1، Fs/F1 و دوره تحلیلی
- محاسبه Fs و F1 با درون‌یابی خطی از جدول‌های ۱-۲ و ۲-۲ برای زمین‌های I تا V؛ زمین نوع VI به‌درستی نیازمند طیف ویژه ساختگاه اعلام می‌شود
- محاسبه Te، T، SMS، SM1، SDS، SD1، T0، Ts، Sa(T)، Cmin، C و K
- نمودار طیف افقی مطابق چهار شاخه فرمول اکسل
- طبقه‌بندی گروه لرزه‌ای و SDC برای مقادیر Ie موجود در جدول اکسل
- کنترل عددی ارتفاع برای ۴۲ ردیف جدول ۱-۳ و همگام‌سازی Ru با سیستم انتخابی؛ یادداشت‌های شرطی و استثناها فقط به‌صورت هشدار نمایش داده می‌شوند و خودکار تأیید نمی‌شوند
- توزیع نیروی جانبی طبقات بر اساس Wi·hi^K
- کپی گزارش متنی و جدول نیروها
- آزمون‌های واحد پایه
- پشتیبانی از جداکننده مطمئن برای وزن طبقات و تحمل خطای اعشاری در نگاشت Ie به SDC

## ساخت محلی APK
Flutter SDK و Android SDK را نصب کنید، سپس از پوشه پروژه اجرا کنید:

```bash
flutter create . --platforms=android --project-name=standard_2800_v5
flutter pub get
flutter test
flutter build apk --release
```

خروجی: `build/app/outputs/flutter-apk/app-release.apk`

## ساخت APK و AAB با GitHub Actions
1. کل پوشه پروژه را در یک مخزن GitHub بارگذاری کنید.
2. از تب **Actions** گردش‌کار **Build Standard 2800-V5 Android** را اجرا کنید (یا روی شاخه main/master پوش کنید).
3. پس از موفقیت، از بخش Artifacts فایل `standard-2800-v5-android-builds` را دریافت کنید؛ این Artifact شامل APK برای آزمایش و AAB برای آماده‌سازی انتشار است. فایل AAB تا زمان تنظیم امضای انتشار، لزوماً برای بارگذاری مستقیم در فروشگاه آماده نیست.

## محدودیت‌های فنی
این نسخه با Flutter در محیط فعلی کامپایل نشده است، چون Flutter/Android SDK در محیط توسعه موجود نبود. بنابراین پیش از توزیع، باید build و تست واقعی روی دستگاه انجام شود. همچنین فرمول‌ها از فایل اکسل استخراج شده‌اند و هنوز تمام بندهای استاندارد رسمی، اصلاحیه‌ها و مثال‌های مرجع به‌صورت مستقل اعتبارسنجی نشده‌اند.

موارد تکمیل‌نشده: بانک شهر برای تعیین Ss/S1، طیف قائم و ویژه ساختگاه، کنترل خودکار تمام شروط یادداشت‌های جدول ۱-۳، کنترل نامنظمی‌ها، ذخیره پروژه‌ها و خروجی PDF/Excel. ابزار فعلی جایگزین بررسی مهندس مسئول و متن رسمی استاندارد ۲۸۰۰ ویرایش پنجم نیست.

## گردش‌کار خودکار ساخت
فایل `.github/workflows/android.yml` اضافه شده است. این گردش‌کار با اجرای دستی از تب Actions یا با push به شاخه main/master، فایل‌های Android را تولید می‌کند، آزمون‌ها را اجرا می‌کند و APK و AAB را به‌عنوان Artifact بارگذاری می‌کند. AAB انتشار عمومی باید با کلید بارگذاری معتبر امضا شود. اگر آزمون‌ها شکست بخورند، APK به‌عنوان ساخت موفق منتشر نمی‌شود.


## اصلاح مهم در بازبینی آیین‌نامه

در بازبینی بند ۳-۹-۳-۲-۱ استاندارد ۲۸۰۰ ویرایش پنجم، محاسبه Cmin اصلاح شد: مقدار پایه `max(0.044 × SDS × Ie, 0.01)` در همه حالت‌ها اعمال می‌شود و فقط اگر `S1 >= 0.6` باشد، حد پایین `0.5 × S1 / (Ru / Ie)` نیز کنترل می‌شود. بنابراین این بخش دیگر عین شرط ناقص فایل اکسل را تکرار نمی‌کند. آزمون واحد مربوطه به‌روزرسانی شده، اما به‌دلیل نبود Flutter SDK، اجرای آزمون و ساخت APK هنوز انجام نشده است.


## نتیجه بازبینی بند زمان تناوب

متن PDF رسمی موجود در پروژه برای روابط تجربی بند ۲-۹-۳-۱، روابط (۶-۳) تا (۹-۳) را به‌ترتیب با توان‌های ۰٫۸، ۰٫۹، ۰٫۷۵ و ۰٫۷۵ مشخص می‌کند. در نسخه قبلی، روابطی که ضریب ۰٫۰۴۹ داشتند به‌اشتباه با توان ۰٫۷۵۳ محاسبه می‌شدند؛ این توان در کد اصلاح شد و آزمون واحدی برای هر شش گزینه رابط کاربری اضافه شد. این آزمون هنوز در این محیط اجرا نشده است، زیرا Flutter SDK نصب نیست.

توجه: انتخاب سیستم در رابط کاربری فقط نگاشتی ساده‌شده برای انتخاب رابطه تجربی است. طبقه‌بندی نهایی سیستم، ضریب رفتار و ارتفاع مجاز باید از جدول ۱-۳ و بندهای مربوط به استاندارد بررسی شود؛ برنامه فعلاً این کنترل کامل را انجام نمی‌دهد.


## بازبینی ضرایب ساختگاه

بر اساس جدول‌های ۱-۲ و ۲-۲ نسخه PDF استاندارد، انتخاب نوع زمین I تا V و درون‌یابی خطی بین مقادیر جدول برای Fs و F1 اضافه شد. ورودی‌های پایین‌تر از محدوده جدول (Ss<0.5 یا S1<0.2) رد می‌شوند تا برنامه خارج از داده‌های جدول برون‌یابی نکند. برای زمین نوع VI، برنامه از محاسبه جدولی خودداری می‌کند و نیاز به طیف ویژه ساختگاه را اعلام می‌کند. این منطق در آزمون واحد نوشته شده، اما آزمون‌ها هنوز به‌دلیل نبود Flutter SDK اجرا نشده‌اند.


## کنترل محدودیت ارتفاع جدول ۱-۳

فهرست کنترل ارتفاع گسترش یافت تا ۴۲ ردیف جدول ۱-۳ را پوشش دهد و با انتخاب ردیف، مقدار Ru متناظر نیز به‌روزرسانی شود. منطق بررسی، یادداشت ۳ درباره افزایش مشروط ارتفاع و استثناهای یادداشت‌های ۶ و ۷ را به‌صورت هشدار آشکار می‌کند، اما شروط آن‌ها را خودکار ارزیابی نمی‌کند. انتخاب سیستم در هر امتداد، جزئیات یادداشت‌های [1] تا [7]، کنترل سیستم‌های دوگانه و تأیید مهندس مسئول همچنان دستی است. آزمون‌های این بخش نوشته شده‌اند ولی هنوز در محیطی با Flutter SDK اجرا نشده‌اند.


## گسترش فهرست جدول ۱-۳ و هشدار استثناها

فهرست ارتفاع به ۴۲ ردیف سیستم سازه‌ای جدول ۱-۳ گسترش یافته است. با تغییر ردیف سیستم مقاوم جانبی، مقدار Ru متناظر جدول در ورودی ضریب رفتار به‌روزرسانی می‌شود؛ ورودی رابطه تجربی زمان تناوب همچنان یک انتخاب ساده‌شده و مستقل است. اگر ارتفاع از حد پایه بیشتر باشد، برنامه موارد مربوط به یادداشت ۳ را فقط به‌عنوان نیازمند بررسی شروط اعلام می‌کند. برای یادداشت‌های ۶ و ۷ نیز از اعلام قطعی غیرمجاز بودن بدون ذکر استثنای مشروط خودداری می‌شود. این قابلیت، کنترل خودکار شرایط یادداشت‌ها نیست.

## نمونه‌های عددی بازتولیدپذیر (کنترل محاسباتی مقدماتی)

این نمونه‌ها برای کنترل مستقل پیاده‌سازی روابط طیف و ضریب زلزله در برنامه تنظیم شده‌اند. ورودی‌ها، روابط و خروجی‌های زیر با محاسبه عددی مستقل از کد Dart بازتولید شده‌اند؛ این‌ها «مثال رسمی چاپ‌شده در استاندارد» نیستند و به‌تنهایی اعتبار آیین‌نامه‌ای برنامه را اثبات نمی‌کنند. ضرایب ساختگاه در مثال‌های B و C از نقاط جدول‌های پیاده‌سازی‌شده انتخاب شده‌اند.

### مثال A — ساختمان ۱۵ متری، مطابق ورودی پیش‌فرض فایل Excel

ورودی‌ها: `H=15 m`, `Ie=1.0`, `system=2`, `Ru=4.5`, `Ss=1.4`, `S1=0.6`, `Fs=1.0`, `F1=1.3`, `Ta=1.0 s`.

| خروجی | مقدار |
|---|---:|
| `Te` | 0.537749 s |
| `T=min(1.4Te,Ta)` | 0.752849 s |
| `SMS` / `SM1` | 1.400000 / 0.780000 g |
| `SDS` / `SD1` | 0.933333 / 0.520000 g |
| `T0` / `Ts` | 0.111429 / 0.557143 s |
| `Sa(T)` | 0.690709 g |
| `Cmin` | 0.066667 |
| `C` | 0.153491 |
| `K` | 1.126425 |
| `V` برای `W=10,000 kN` | 1,534.91 kN |

### مثال B — ساختمان ۳۰ متری با `S1 < 0.6`

ورودی‌ها: `H=30 m`, `Ie=1.2`, `system=1`, `Ru=6.5`, `Ss=1.0`, `S1=0.4`, `Fs=1.1`, `F1=2.1`, `Ta=2.0 s`.

| خروجی | مقدار |
|---|---:|
| `Te` | 1.094031 s |
| `T` | 1.531643 s |
| `SMS` / `SM1` | 1.100000 / 0.840000 g |
| `SDS` / `SD1` | 0.733333 / 0.560000 g |
| `T0` / `Ts` | 0.152727 / 0.763636 s |
| `Sa(T)` | 0.365620 g |
| `Cmin` پایه | 0.038720 |
| `C` | 0.067499 |
| `K` | 1.515821 |
| `V` برای `W=10,000 kN` | 674.99 kN |

این مثال به‌طور خاص کنترل می‌کند که وقتی `S1 < 0.6` است، حد پایه `Cmin=max(0.044 SDS Ie, 0.01)` حذف نشود.

### مثال C — کنترل شاخه `S1 ≥ 0.6`

ورودی‌ها: `H=70 m`, `Ie=1.4`, `system=3`, `Ru=6.5`, `Ss=1.5`, `S1=0.6`, `Fs=1.1`, `F1=2.8`, `Ta=3.0 s`.

| خروجی | مقدار |
|---|---:|
| `Te` | 1.185822 s |
| `T` | 1.660151 s |
| `SMS` / `SM1` | 1.650000 / 1.680000 g |
| `SDS` / `SD1` | 1.100000 / 1.120000 g |
| `T0` / `Ts` | 0.203636 / 1.018182 s |
| `Sa(T)` | 0.674637 g |
| `Cmin` پایه | 0.067760 |
| `C` | 0.145307 |
| `K` | 1.580076 |
| `V` برای `W=10,000 kN` | 1,453.07 kN |

در این مثال، مقدار `Cmin` نهایی برابر حد پایه است؛ بنابراین آزمون شاخه دوم `0.5 S1/(Ru/Ie)` نیز باید جداگانه در ورودی‌ای آزموده شود که این حد از حد پایه بزرگ‌تر شود.

### محدودیت استفاده از این نمونه‌ها

- `V=C×W` در این گزارش صرفاً کنترل ساده ضریب بر وزن لرزه‌ای واردشده است؛ ترکیب بار، وزن لرزه‌ای صحیح، ضوابط توزیع قائم، پیچش، نامنظمی‌ها و کنترل‌های تحلیل سازه را جایگزین نمی‌کند.
- ضرایب `Fs` و `F1` باید با نوع زمین و مقادیر طیفی معتبر پروژه تعیین شوند؛ بازه‌های خارج از جدول یا زمین نوع VI نیازمند بررسی ویژه‌اند.
- خروجی‌ها هنوز با یک مثال رسمی عددی از مرجع آیین‌نامه به‌صورت سرتاسری تطبیق نشده‌اند. آزمون‌های Flutter نیز تا زمان اجرای محیط Flutter، اجراشده محسوب نمی‌شوند.
